## 6. 캡션 지침과 로컬 LLM 실행 방식

캡션 지침은 `G:\fizgig\Fizgig_auto\automation\caption_instructions.txt`에 분리했다. 사진에서 확인할 수 있는 머리 모양, 옷과 색, 자세, 표정, 구도, 촬영 각도, 조명, 배경을 영어 약 60~100단어로 설명하도록 구성했다. 인물의 이름을 추측하거나 미적 평가를 붙이지 않도록 했다. 트리거는 실행기가 추가한다.

원본에 같은 이름의 비어 있지 않은 `.txt` 캡션이 있고 작업 사본의 캡션 파일이 없으면 우선 복사한다. 같은 작업 버전에서 이미 존재하는 비어 있지 않은 캡션은 재개 시 건너뛴다. 캡션 요청에는 EXIF 방향을 반영하고 최대 1024×1024 범위로 축소한 JPEG 이미지를 넣는다. 출력의 `<think>…</think>` 제거와 불완전한 응답 거부를 구현했지만, 모든 모델의 사고 과정 표식을 지원한다고 검증한 것은 아니다.

`local_caption.py`는 `http://127.0.0.1`, `http://localhost`, `http://[::1]`의 `/v1` 주소만 허용하고 프록시와 리다이렉트를 차단한다. 로컬 서버가 준비됐고 모델 별칭이 일치하면 재사용하고, 실행기가 직접 시작한 서버만 캡션 종료 후 닫도록 구현했다. 실제 자동 시작·캡션 생성·종료와 GPU 메모리 반환을 확인했다는 이전 기록이 있으며, 이번 재검토에서는 모델 서버를 다시 시작하지 않았다.

기존에 사용자가 실행한 서버는 자동으로 종료하지 않는다. `execute()`는 **설정한 캡션 주소의 포트가 열려 있으면** 캐시·학습 실행 전에 중단한다. GPU 사용량이나 전체 GPU 프로세스를 검사하는 것은 아니므로, 다른 포트의 LLM·ComfyUI 작업을 탐지하는 기능으로 해석하면 안 된다.

LLM 프로필에는 사용자 배치 파일, Q4_K_M GGUF 모델, BF16 mmproj 경로가 저장돼 있다. 최근에는 배치 파일 방식 외에 llama-server 실행 파일과 GGUF/mmproj를 직접 지정하는 방식도 추가했지만, 이 직접 실행 방식은 아직 검증하지 않았다.

## 7. TODO 및 학습 자동화 코드

`runner.py`에 다음 기능을 구현했다.

- `doctor`: Python·CUDA, 서버 준비 여부, 모델·실행 파일 경로와 데이터 목록 점검. 실제 캡션·캐시·학습 성공 검사는 아니다.
- `prepare`: 원본 사본 생성, 정확히 같은 파일 중복 제거, 손상 검사, 데이터 목록 저장.
- `caption`: 기존 캡션 재사용 및 부족한 사진의 로컬 캡션 생성. `--limit`으로 일부만 처리 가능.
- `plan`: 사진 준비 후 캡션·모델 조건을 검사해 네이티브 학습 명령을 `launch_plan.json`에 저장. GPU 학습은 실행하지 않지만 작업 폴더·manifest를 생성할 수 있다.
- `run`: 활성 TODO 작업의 캡션·캐시·학습을 순차 실행.
- `status`: 현재 설정·원본·지침으로 계산한 작업 버전의 `state.json` 조회. 과거 실행 폴더 전체를 나열하지 않으며 원본 폴더 접근과 정상 설정이 필요하다.

작업 버전은 병합된 설정 전체, 원본 경로·이미지 SHA-256·원본 캡션, 캡션 지침으로 계산한다. 따라서 학습률·스텝·LLM 대기 시간 같은 설정 변경도 새 작업 버전을 만들 수 있다. 이전 작업 폴더에서 캡션을 자동으로 찾아 이관하는 기능은 없다.

큐 잠금, 단계별 로그, 완료 단계 재사용, 마지막으로 완전히 저장한 학습 상태에서 재개하는 코드도 작성했다. 실제 캐시와 학습 재개는 아직 실행 검증하지 않았다. `state.json`은 캐시·학습 실행 과정에서 작성되므로, 캡션까지 완료돼 있어도 `status`는 `not started`를 표시할 수 있다. 캡션 완료 여부는 `images`의 파일과 사용량 로그로 따로 확인해야 한다.

**작업 사본의 캡션·이미지 수정은 버전 계산에 포함되지 않는다.** 완료 캐시 단계도 `state.json`의 이름만 보고 건너뛰므로, 캐시 이후 캡션을 편집하거나 캐시 파일이 손상·삭제됐을 때 자동으로 재생성된다고 보장할 수 없다. 캐시 무효화와 산출물 검증은 보완 과제다. `dataset_manifest.json`에는 전체 실행 설정 사본도 저장되지 않는다.

현재 TODO는 `eunbi_waterbomb` 1개이며, 트리거는 `eunbiwb`, 시드는 42다. 기본 데이터 폴더 외에 작업별 데이터 폴더와 목표 스텝·rank 등을 지정할 수 있다. 별도 승인 질문 없이 순차 처리하는 CLI 흐름을 구현했으며, 전용 승인·검수 상태를 관리하는 기능은 아직 없다.

### 복구 전 문제와 처리 결과

복구 전 `config.json`에는 다음 문제가 있었다.

```text
caption_model = gpt-4.1-mini
caption_base_url 등 로컬 연결 필수 설정 없음
```

복구 전 TODO를 `runner.settings()`에 넘겨 **`KeyError('caption_base_url')`를 실제 재현했다.** `doctor`, `prepare`, `caption`, `plan`, `run`, `status` 모두 이 설정 처리를 거치므로 환경 검사부터 정상 완료할 수 없었다. 설정 복구로 이 오류는 해소됐다. 다만 `runner.py`의 최상위 예외 처리는 여전히 `ValueError`, `RuntimeError`만 처리하므로, 필수 키가 다시 누락되면 친절한 설정 안내 대신 traceback으로 노출되는 코드 보완 과제는 남아 있다.

`G:\fizgig\Fizgig_auto\automation\llm_profiles.json`의 `Gemma 4 31B · 64K` 프로필을 기준으로 모델명을 `gemma4-31b-qat-uncen`으로 되돌리고, 로컬 주소·배치·GGUF·mmproj 경로·자동 시작·대기 시간을 `config.json`에 복구했다. 현재 프로필의 모든 키·값이 일치한다. 데이터 폴더, 목표 스텝, rank, 학습률, 샘플 프롬프트와 TODO는 유지했다. 과거 설정이 달라진 원인은 확인하지 않았다.

복구한 실제 설정과 현재 TODO로 `context()`를 계산한 결과, 기존 완료 폴더 `eunbi_waterbomb-d3a9b48e1970278f`와 정확히 일치했다. 사진 32장 각각에 비어 있지 않은 캡션이 있음을 확인하고 `captions()`를 호출해 `All captions already present; Gemma load skipped.`를 확인했다. 기존 산출물을 수정하거나 새 작업 버전을 만들지 않았다. `caption_launch_mode: "batch"` 같은 새 키를 추가하는 것만으로도 해시는 달라질 수 있어, 복구에는 프로필의 기존 키·값만 사용했다.

### 14.7 사람 점수 결과 — Krea2 구성 확정 (확인 완료, 2026-11-05)

시트에 사용자가 직접 채점했다(판정 93건, 그중 숫자 없이 `다른 캐릭터/심한 오류`만 표시한 25건). 점수는 **1 = 나쁨, 5 = 아주 좋음**이고, 추천은 가중 점수(정체성 0.45 / 지시 준수 0.30 / 품질 0.25)가 가장 높은 방식을 고른다.

| 방식 | 판정 | 정체성 | 지시 준수 | 품질 | 가중 | 다른 캐릭터/오류 |
| --- | --- | --- | --- | --- | --- | --- |
| **krea2_b_e028 (RAW+가속 LoRA+캐릭터 LoRA)** | 24 | 4.46 | 4.71 | 4.88 | **4.64** | 0 (0%) |
| krea2_a_e028 (Turbo+캐릭터 LoRA) | 24 | 4.08 | 4.71 | 4.88 | 4.47 | 0 (0%) |
| qwen_edit (툴2 기존 산출물) | 21 | 4.10 | 3.10 | 4.05 | 3.79 | 2 (10%) |
| krea2_c_e028 (레퍼런스 조건) | 24 | - | - | - | - | **24 (100%)** |

카테고리별 가중 점수: (b)는 각도 4.71·포즈 4.89·배경 4.49·표정 4.60·프레이밍 4.44로 모든 범주에서 (a)와 같거나 높다. (a)는 각도 4.42·포즈 4.55.

정체성이 갈린 16개 슬롯 중 **(b)가 12개에서 우세**, 특히 전신·측면·포즈에서 벌어졌다(`ang_front_wide` 4→5, `ang_back_medium` 4→5, `bg_park` 3→5, `pos_sitting`/`pos_walking`/`pos_waving` 모두 4→5). (a)가 나은 4개는 1점 차이였다.

**결론 3가지**

1. **구성 (c)는 탈락한다.** 24장 전부가 "다른 캐릭터"로 판정됐다. 스타일 레퍼런스 LoRA(`krea2_style_reference`)가 캐릭터 LoRA보다 강하게 작동해 정체성을 덮어쓴다. §4 M0의 "동작하면 포함하고, 안 되면 사유를 기록하고 뺀다"에 따라 **사유를 남기고 제외**한다. 그래프 빌더와 검사는 남겨 두므로, 나중에 LoRA 강도를 낮추는 방식으로 재시도할 수 있다.
2. **Krea2 경로가 툴2 Qwen 편집보다 낫다.** 지시 준수 4.71 대 3.10, 품질 4.88 대 4.05로 크게 앞서고 정체성도 동등 이상이다. 툴2는 원본에 앵커링된 편집이라 슬롯 지시를 잘 따르지 못하고, 전신(`ang_front_wide` 정체성 1점)과 측면·후면에서 무너진다 — §1.2의 추정이 데이터로 확인됐다.
3. **추천 구성은 (b) RAW DiT + 가속 LoRA + 캐릭터 LoRA** (가중 4.64). 다만 2위 (a)와의 차이가 **0.17로 자체 기준(0.2) 미만**이라, 시드를 늘리기 전에는 확정으로 보기 어렵다. 정체성(가중 0.45)에서 4.46 대 4.08로 앞서고 16개 슬롯 중 12개에서 우세한 점이 근거다.

**집계 버그를 하나 발견해 고쳤다.** 사용자가 숫자 없이 `다른 캐릭터/심한 오류`만 표시한 행(25건)을 `score_rows`가 통째로 버려서, (c)가 집계표에서 아예 사라지고 오류율도 낮게 잡혔다. 이제 오류 표시만 있는 행도 판정 수(n)와 오류율에 포함하고, 숫자 없는 건수를 `숫자 없음` 열로 따로 보여준다. 추천에서 제외된 방식은 `## 탈락` 절에 사유와 함께 명시한다.

**채점 UI도 사용자 요청으로 바꿨다.** 숫자 입력 대신 **1~5 버튼 클릭**(같은 숫자를 다시 누르면 해제)으로 바꾸고, 시트 상단에 "1 = 나쁨, 5 = 아주 좋음"과 가중치를 명시했다. 숫자 없이 오류만 표시하는 것도 정상 동작한다.

### 15.2 작업 버전과 캐시 분리 (확인 완료)

- `state.json`에 `family`/`arch_id`를 기록하고, 다른 family의 상태를 만나면 그 실행을 이어받지 않고 처음부터 시작한다고 알린다.

### 15.4 캡션 프로필과 정책 (구현 완료)

- `kind: photo | anime`로 지침 파일을 고른다. `photo`는 기존 `caption_instructions.txt`, `anime`은 새 `caption_instructions_anime.txt`(Danbooru 태그 + 문장, 툴2의 Qwen3-VL 프롬프트를 로컬 모델용으로 옮긴 것)다. 어느 파일을 썼는지가 캡션 식별자에 들어가므로, kind를 바꾸면 캡션이 섞이지 않고 새로 만든다.
- `caption_policy`:
  - `missing-only`(기본, 기존 동작): 캡션이 없는 이미지만 만든다. 있는 캡션은 건드리지 않는다.
  - `preserve`: 캡션을 새로 만들지 않는다. 캡션이 빠진 이미지가 있으면 조용히 만들지 않고 **사유를 밝히며 실패**한다(직접 손본 데이터셋을 덮어쓰지 않기 위해).
  - `explicit-recaption`: 모든 캡션을 다시 쓴다. 캡션 스타일만 다른 스냅샷 2개를 비교할 때(§7 Q4) 쓴다.

## 16. 데이터셋 파이프라인 M2 — 툴2 보강과 생성기 A 연동 — 2026-11-06 (한국 시간)

근거 명세: `TASK_SPEC_dataset_pipeline.md` §4 M2. 툴2(`qwen 2.1 edit`)를 처음 손댄 단계다. 툴2는 `3e83174`로 현 상태를 보존해 두었으므로 되돌릴 수 있다.

### 16.1 알려진 버그 2건 수정 (확인 완료)

`adopt()`가 **AI 캡션 딕셔너리**를 **손편집 여부 플래그**에 덮어쓰고 있었다. 하나의 이름이 두 가지를 가려서:

- 손편집 캡션이 기계가 쓴 것으로 보여 **재구성된 AI 캡션으로 덮어써졌다**.
- `autocaption.json`이 없거나 비면 기록 승계가 빠져, 나중에 태그를 고쳐도 그 캡션에 닿지 못했다.

두 사실을 다른 이름(`machine_written` / `auto`)으로 분리했다. 웹 UI는 `db.adopt(out_dir, back, t)`를 3인자로 호출하고 있었고(함수는 5인자) 그래서 번호가 바뀐 이미지를 복원하면 `TypeError`가 났다. 이제 `cfg, char`를 함께 넘긴다.

툴2의 **첫 검사 파일** `test_dataset_batch.py`를 만들었다(툴2 자체 인터프리터로 실행). **고치기 전 코드에서는 14개 중 6개가 실패**해 두 버그를 정확히 지목한다 — `adopt()` 관련 4건(기록 승계 누락 2건, 손편집 덮어쓰기 1건, 기록 없음 1건)과 앱 호출 2건(하나는 `(call='adopt', line=414)`로 호출 위치까지 알려준다). 고친 뒤 14개 전부 통과한다. `dataset_app.py`의 모든 `db.<함수>(...)` 호출이 `dataset_batch`가 선언한 인자 수와 맞는지 검사하는 항목도 넣었다 — 이런 종류의 버그는 사용자가 먼저 그 경로를 찾아야만 드러나기 때문이다.

### 16.2 재개 키 보강과 기존 데이터 마이그레이션 (확인 완료)

키에 **그래프 버전**(`GRAPH_VERSION = "qwen_edit21@1"`)과 **모델 파일의 내용 해시**(`quick_hash`: 크기+mtime+앞뒤 4MB, 작은 파일은 전체 sha256)를 넣고 길이를 6자에서 **12자**로 늘렸다. 모델 이름이 아니라 내용이 들어가므로 같은 이름으로 다시 내보낸 모델도 구분한다. 캡션은 키에서 빠져 있어 태그만 고치면 이미지는 재생성되지 않는다(검사로 고정).

**기존 데이터셋이 재생성되지 않는다는 것이 핵심이다.** 옛 공식(모델 *이름* 기반 6자)을 `legacy_png`/`legacy_job`으로 함께 계산해 두고, 새 이름의 파일이 없으면 옛 이름의 파일을 `adopt()`한다. 실제 `dataset/수아맘`(55장)에 대해 계획을 돌린 결과 **55개 작업 전부가 옛 파일을 찾았고 재생성 대상 0건**이었다. 복사본에 실제 CLI를 돌려 **55장 전부 "adopted from the previous key length"로 건너뛰고 생성 0건**, 파일 55개가 12자 키로 바뀌고 캡션 55개가 그대로 남는 것을 확인했다.

기각 이력도 유지된다: 파일명만 보면 키가 바뀌어 기각한 이미지가 되살아나므로 작업 판정은 `legacy_job`까지 함께 본다(검사 있음). 실제 데이터셋에는 `_rejected` 폴더가 없어 해당 사례는 없었다.

### 16.3 부분 저장 방지와 prompt_id 영속화 (확인 완료)

- 이미지·JSON은 임시 이름에 쓴 뒤 `os.replace`로 확정한다. 반쪽 PNG는 없는 것보다 나쁘다 — `png.exists()`가 "이미 했다"의 근거이므로 반쪽 파일은 영원히 건너뛰어지고 학습에 들어간다.
- `_pending_prompts.json`에 **제출 직후** prompt_id를 기록한다. 중간에 죽으면 다음 실행이 `/history`에 물어보고, 이미 만들어진 그림은 내려받아 저장하고 **다시 제출하지 않는다**. 서버가 모르는 id(재시작)면 기록을 지우고 정상 재생성한다. 파일이 저장된 뒤에는 기록을 지운다(검사에서 이 누락을 잡아 고쳤다).

### 16.4 프로세스 간 잠금 (확인 완료)

`FolderLock`이 출력 폴더에 PID·시각·명령을 적는다. 살아 있는 소유자가 있으면 거부하고, 죽은 프로세스의 잠금은 회수한다. 같은 프로세스의 두 번째 기록자도 거부한다(중첩 실행이 서로 파일을 rename하는 것을 막기 위해). `run_dataset`/`run_captions`에 데코레이터로 붙여 **CLI와 웹 UI가 각자 기억할 필요 없이** 보장된다. 웹 UI의 `busy_with()`는 *다른* 프로세스가 잡은 잠금을 보고 거부한다(자기 작업은 기존 JOB 검사가 담당).

### 16.5 자동화용 CLI (확인 완료)

| 옵션 | 내용 | 실제 확인 |
| --- | --- | --- |
| `--result-json PATH` | 버전 있는 결과 JSON(생성/스킵/실패 목록, 파일, 파라미터) | `version=1`, `graph_version=qwen_edit21@1`, planned 55 / skipped 55 |
| `--events` | stdout에 JSON Lines, 사람용 로그는 stderr로 이동 | stdout이 **정확히 57줄의 JSON**(run 1, image 55, summary 1), 산문 없음 |
| `--cancel-file PATH` | 이 파일이 생기면 진행 중 prompt를 drop하고 종료 | exit 1, `run` 이벤트 1개만 남고 "cancelled" |
| `--fix-jobs PATH` | `[{input, refs[], prompt, seed, out}]` — image1=고칠 그림, image2..n=원본 레퍼런스, consistency LoRA | **실제 GPU: 42초, 1.4MB PNG 생성**, 결과 JSON에 파라미터 기록 |

결과 행에는 `seed`/`prompt`/`steps`/`cfg`/`resolution`/`lora`/`refs`가 들어가 호출자가 툴2의 manifest를 읽지 않고도 후보를 기록할 수 있다. 여기서 **버그를 하나 더 잡았다**: 캡션 대신 작업 딕셔너리를 결과 행에 넣어 `Path` 객체가 JSON 직렬화에 실패했다(검사가 잡음).

`--fix-jobs`/`--config`는 사람이 쓰는 파일이므로 **BOM을 허용**한다(`utf-8-sig`). 실제 실행에서 PowerShell이 쓴 BOM 때문에 실패해 드러난 문제다. 캡션·manifest·autocaption 읽기도 함께 관대하게 바꿨다.

### 16.6 생성기 A: 툴1 ↔ 툴2 연결 (확인 완료)

`automation/pipeline/gen_qwen_edit.py`. 프로젝트 설정으로 **실행별 스냅샷**을 만들어 툴2 CLI에 넘기고 결과를 `candidates.jsonl`로 들여온다.

- 스냅샷은 툴2 설정, 캐릭터 항목, **입력 이미지 바이트**, 툴2의 그래프 버전을 묶어 id를 만든다(`sha256[:12]`). 입력은 복사하므로 나중에 원본을 고쳐도 이 실행의 결과가 달라지지 않는다.
- 툴2의 그래프 버전은 **툴2 소스에서 직접 읽는다**(`GRAPH_VERSION`). 코드를 복사하지 않고 상수 하나만 읽는 것이라 D1에 어긋나지 않는다. 실패하면 "unknown"으로 기록하고 추측하지 않는다.
- 합성 입력 판정: 카드의 `synthetic_sources`가 1순위, 없으면 툴2 자신의 후보 파일 접두사(`anchor_refined_` 등)를 근거로 삼고 **판정 근거를 함께 기록**한다. 명세가 든 예(`anchor_refined_fullbody_*`)가 `synthetic`으로, 실제 원본은 `user`로 잡히는 것을 확인했다.
- 계보: 후보는 세대 1, 편집 깊이 1, `parent_ids`는 스냅샷 안 원본의 source id다. 실제 실행에서 16개 입력(합성 1 + 원본 15) 중 부모가 스냅샷 source로 해석되는 것을 확인했다.
- 홀드아웃용 `exclude` 인자를 미리 지원한다(§7 Q6에서 사용).

실제 실행: `--only framing --limit 1` → 스냅샷 `b4e7b971906f`, 툴2가 1장 생성, 후보 1건 기록(`graph_version: tool2:qwen_edit21@1`, 부모 1개 해석).

ComfyUI를 **UTF-8 환경 없이** 띄우면 커스텀 노드 로딩 실패를 로그로 남기다가 로거가 죽는다(`'cp949' codec can't encode '\U0001f389'`). 프로세스가 통째로 종료된다. `PYTHONUTF8=1`·`PYTHONIOENCODING=utf-8`을 주면 16초에 정상 기동한다. 툴2의 `start_comfy()`가 이미 그 환경을 넣고 있는 이유가 이것이다.
